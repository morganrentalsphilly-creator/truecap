A single absence hours after a single presence is far more likely result-set

because that is what was observed, and it means the baseline's "the

**The staging-duplicate fix has not taken effect.** The baseline listed

200-OK page only removes the URL after Google recrawls it, which for a
low-priority alias can take weeks. Until then a complete duplicate of the

## Part D — this week's single highest-leverage action

> **CORRECTION 2026-08-03 — this recommendation is impossible and was
> re-proposed for a month.** A 308 in `proxy.ts` runs on OUR deployment.
> `truecap-iota.vercel.app` is a different Vercel project and never runs this
> code, so no redirect, header or middleware change here can affect it. The
> only fix is deleting that project in the Vercel account that owns it.
> See `docs/seo/foreign-deployment-truecap-iota.md`. The text below is kept
> as written for the record.

**Make the non-canonical host guard a 308 redirect to usetruecap.com on
production deployments, instead of `noindex` alone — then request removal of
`truecap-iota.vercel.app` in Search Console.**

Evidence from this run: it is the only thing measured that is *actively
outranking the real domain* (first result for `"TrueCap" rental calculator`,
above usetruecap.com), and the page is still live and serving the whole site.
`noindex` is the slow instrument here — it needs a recrawl of a URL Google has
no reason to recrawl soon. A redirect is acted on at the next fetch, collapses
the duplicate immediately, and consolidates whatever equity the alias has
accumulated into the canonical domain instead of discarding it.

Concretely, in `applyHostGuard` (`proxy.ts:40`):

- If the host is non-canonical **and** `process.env.VERCEL_ENV === "production"`
  → return `NextResponse.redirect(<same path + query on https://usetruecap.com>, 308)`.
- Otherwise (`VERCEL_ENV === "preview"`, or local) → keep the current
  `X-Robots-Tag: noindex, nofollow` behaviour untouched.

Gating on `VERCEL_ENV` is what keeps this safe: `truecap-iota.vercel.app` is a
production alias and gets redirected, while per-PR preview deployments stay
fully browsable for review. Redirecting *all* non-canonical hosts would break
preview review, so do not skip the gate.

Then submit a removal request for the alias in Search Console and re-check the
brand query in next week's snapshot — this is the one item in this file with a
verifiable one-week outcome.

Why this over the alternatives: the aggregator submissions (Part B) are the
higher *ceiling* play and should follow close behind — `proplab.app` and
`dealrun.ai` are freshly identified, low-bar targets. But they depend on
third-party editorial timelines and can't be completed today. This is a
code change shippable today that removes the site's only measured active
competitor for its own name.
